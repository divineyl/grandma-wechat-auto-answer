# 不会自动接听时对照

先确认跑的是仓库里的 `auto-answer-fullscreen.js`，平板停在**桌面**再打测试电话。

## 1. 脚本还在不在跑

1. AutoJs6 里这条脚本必须显示**正在运行**（不要被音量键停掉）。
2. 设置 → 无障碍 → AutoJs6 **开着**。打测试电话前再看一眼，小米有时会关。
3. 设置搜索 **通知使用权** / **通知监听**：AutoJs6 先关掉再打开，然后回 AutoJs6 **重新运行**脚本。
4. 设置搜索 **后台弹出界面**：AutoJs6、微信都选始终允许。

## 2. 看有没有「检测到微信来电」

打过来时应弹出「检测到微信来电，正在接听」。

- **没有这句**：通知没监听到。重点做通知使用权、微信横幅/锁屏通知、后台弹出。
- **有这句但仍不接**：来电界面选择器对不上。把来电那一屏截图发到 GitHub Issue（打码家人头像即可）。

锁屏有密码时先把屏幕亮着、停在桌面再试。

## 3. 重启后必须重新点运行

这是正常的，不是脚本坏了。按 [keep-running.md](keep-running.md) 设定时任务和开机启动。

## 4. 只有通知、没有大接听按钮

微信没被允许从后台弹全屏。按 [xiaomi.md](xiaomi.md) 打开微信的后台弹出界面、悬浮窗、横幅通知，并锁定最近任务。

## 5. 过几分钟就失效

省电策略不是无限制，或最近任务没锁。AutoJs6 打开前台服务。

## 6. 点了接听但没声音

平板音量；通话界面里扬声器是否仍显示「已关」。脚本会尝试点「扬声器已关」。

## 7. 陌生人打来也会接

这是默认行为。家庭专用机一般可以。不要把自动接听装在会随便加人的设备上。

## 8. 运行中弹出「自动接听已经停了」

这是故意停的。脚本已经在跑，后来发现无障碍或通知使用权没了，或者一时确认不了，就会停下来。停了之后不会再点屏幕，也不会去猜按钮在哪里。开关如果自己又好了，脚本也不会接着接，必须重新运行。

请家人：

1. 打开系统设置，搜索「无障碍」，确认 AutoJs6（打包后可能叫「微信接听」）是开的
2. 再搜索「通知使用权」（有的手机叫「通知监听」），同样确认是开的
3. 回到 AutoJs6，重新运行 `auto-answer-fullscreen.js`。`access-watch.js` 仍要在同一个文件夹
4. 看到「全屏自动接听运行中」之后，再打一次测试电话

不要在这条提示还在的时候继续打。那时平板不会自己接。

脚本只看这两项：无障碍服务是否还连着、系统里这两项开关是否还开着。它看不到「自启动」有没有被关掉。自启动丢了通常是脚本整个没在跑，而不是这条提示。

## 9. 仍可能失败

- 微信改版后面按钮文案变了
- 平板厂商把无障碍点按做得很严
- 来电出现在系统小岛/胶囊里，而不是微信自己的界面
